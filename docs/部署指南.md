# AnimeViewer 部署指南

> 版本：v1.1 ｜ 日期：2026-09-26 ｜ 适用：前端 v0.30 + AnimeViewerService 0.30.0（Web 形态）/ 桌面版 1.0.0（feature/v1.0-desktop 分支）｜ 状态：§4A 桌面版部署——D1（Tauri 壳）+ D2（内置服务 sidecar）已交付（2026-09-26），D3 随包二进制待交付；§1/§2 同步桌面版口径。前版 v1.0：2026-09-25 评审通过（Web 形态全量）

## 1. 组件与形态

| 组件 | 必需性 | 说明 |
|---|---|---|
| 前端 SPA | 必需 | Vue 3 + Vite 构建产物 `dist/`（Hash 路由，静态托管零 rewrite）；不部署服务端时可独立使用（在线 API 或内置演示数据） |
| AnimeViewerService | 可选 | Java 21 + Spring Boot 3.5.x 单 jar；提供本地媒体库扫描匹配/流播放（mkv 转封装、实时转码）、BT 下载（aria2）、订阅自动化、AI 分析；数据落 SQLite 单文件 |
| 桌面版（v1.0 规划） | 规划中 | Tauri 2 壳 = 前端 dist + 内置服务端（fat jar + jlink 裁剪 JRE）+ aria2c + ffmpeg/ffprobe 随包（qBittorrent 永不打包，维持直开模式）；NSIS 安装包/绿色 exe 双形态，见 §4A |

## 2. 环境要求

- **服务端**：JDK 21（LTS）；可选外部依赖——`ffmpeg`/`ffprobe`（mkv 转封装/探测/转码，未配置时 mp4 直连降级）、`aria2c`（BT 下载，未配置时降级一键复制磁力）、本机 qBittorrent（直开模式，替代 aria2）
- **前端构建**：Node.js 18+（`npm ci && npm run build`）；生产使用只需任意静态文件服务器
- **桌面版构建（v1.0）**：Rust 工具链（rustup/cargo）+ Tauri CLI + Node.js 18+；**新安装的环境统一装在 `G:\DeskTop` 目录下**（本机构建约定）。最终用户零环境要求（WebView2 Win10/11 自带，缺省时安装包引导下载）
- **浏览器**：Chromium 系（Chrome/Edge）；本地直连播放需支持 File System Access API
- **网络**：api.bgm.tv 在部分网络需代理——前端可配反代/镜像；服务端内置 `auto` 线路容灾（直连失败自动经代理重试）

## 3. 服务端部署（AnimeViewerService）

### 3.1 构建

```bash
# 需 JDK 21（JAVA_HOME 指向 JDK 21；低版本 JDK 会因 UTF-8 源码误读报编译错）
mvn -DskipTests package
# 产物：target/animeviewer-service-<version>.jar（当前 0.30.0）
```

### 3.2 启动

```bash
cd <部署目录>          # 工作目录决定运行数据位置 ./data/
java -jar animeviewer-service-0.30.0.jar
```

- 首次启动自动建数据目录与 SQLite 库（`data/media.db`，建表语句见附录 A），并生成 32 位随机**配对 Token**：打印到控制台「配对 Token:」行 + 写入 `data/token`；
- 常用启动参数覆盖：`--server.port=8787`、`--server.address=0.0.0.0`（**开启局域网监听需显式配置，默认仅绑定 127.0.0.1**）、`--av.scan.auto-on-start=false`（关闭启动即扫描）。

### 3.3 关键配置（application.yml，均可不改用默认值）

| 配置 | 默认 | 说明 |
|---|---|---|
| `server.port` / `address` | 8787 / 127.0.0.1 | 局域网观看才改 0.0.0.0 |
| `av.data-dir` | ./data | Token 与 SQLite 所在目录 |
| `av.ffmpeg-path` / `ffprobe-path` | PATH 探测 | 未入 PATH 填完整路径 |
| `av.bangumi.proxy-mode` | auto | auto（直连失败走代理）/ direct / proxy；`proxy-host/port` 按实际代理修改 |
| `av.proxy.allowed-hosts` | 空（禁用） | 在线流代理域名白名单，仅代理前端手动添加的源 |
| `av.aria2.*` | PATH 探测/回环 16800 | 也可运行期在前端设置页覆盖（存 SQLite settings 表） |
| `av.ai.*` | enabled=false | AI 默认关闭；apiKey 等运行期配置存服务端本地，不进代码库 |

### 3.4 健康检查

`GET http://127.0.0.1:8787/api/health`（带 `X-AV-Token` 头），返回版本与 ffmpeg 可用性。

### 3.5 Token 轮换

删除/替换 `data/token` 后重启（新 Token 打印到控制台），前端设置页重新填入。

## 4. 前端部署

- **开发模式**：`npm install && npm run dev` → http://localhost:5173
- **生产模式**：`npm run build` → 产物 `dist/`，任意静态服务器托管（Hash 路由，无需 rewrite 规则）
- **首次配置**（设置页）：
  1. 数据源模式：在线 Bangumi API（可配 Base URL 反代/镜像、Access Token）或内置演示数据；
  2. 使用媒体服务时：填「服务地址 + 配对 Token」→ 点「连接测试」。

## 4A. 桌面版部署（Tauri 2 · D1~D4 已交付定稿 2026-09-26）

> v1.0 桌面化 **D1（Tauri 壳）/ D2（内置媒体服务 sidecar）/ D3（随包二进制）/ D4（E2E 服务端链路 + 定稿）全部当日交付**，本节转正式。技术论证见技术选型文档 §3.9，阶段实现记录见功能迭代文档 §5 v1.0 节。

**发布物（双形态）**：

| 形态 | 内容 |
|---|---|
| NSIS 安装包（完整版） | 前端 dist + 内置服务端（fat jar + jlink 裁剪 JRE）+ aria2c + ffmpeg/ffprobe 随包（**实测 199MB**） |
| NSIS 安装包（精简版 `-lite`） | 同完整版但不含 ffmpeg/aria2（**实测 80MB**）——轻量用户选此，ffmpeg/aria2 走 PATH 探测降级路径 |
| 绿色 exe | 同形态内容物平铺目录（exe + service\ 平铺），免安装解压即用 |

> D3 落地说明：评审定案「NSIS 组件化（ffmpeg 默认勾选可裁）」以双发布物实现——Tauri 2 NSIS 模板不支持自定义组件选择页，双发布物同效（完整版=默认勾选，精简版=裁剪）。

两种形态数据一律落 `%APPDATA%\AnimeViewer\data`（`--av.data-dir` 注入），不写在程序目录旁（防 Program Files 权限问题）；备份口径同 §6。

**最终用户环境要求**：Windows 10/11 x64，零额外安装；qBittorrent 下载模式需用户自装客户端（检测到已安装则直开，维持 v0.18 定案，永不随包分发）。

**桌面版与传统 Web 部署差异**：

| 事项 | Web 形态（§3/§4） | 桌面版 |
|---|---|---|
| JDK 21 | 必装 | 不需要（jlink 裁剪 JRE 随包，用户无感） |
| ffmpeg / aria2c | 用户自备 PATH 或配置完整路径 | 随包自带，壳启动服务端时经参数注入包内路径 |
| 服务配置 | 前端设置页手填服务地址 + Token | 壳自动桥接：拉起服务端 → 健康检查 → 读 `data/token` 回填（手动配置优先）；设置页保留「内置/外接」开关 |
| 数据目录 | jar 工作目录 `./data` | `%APPDATA%\AnimeViewer\data` |
| 端口 | 8787（HTTP）/ 16800（aria2 RPC 回环） | 同左；8787 被占时壳提示启动失败，Web 功能不受影响 |
| 服务端生命周期 | 用户自行启停 | 壳拉起/退出时收尾；`--av.parent-pid` 心跳防壳崩溃后孤儿进程 |

**构建流水线（开发侧，D2 起已脚本化）**：

```bash
# 0) 构建环境：Rust 工具链 + Tauri CLI（统一安装到 G:\DeskTop）+ Node 18+
# 1) 服务端 jar（需 JDK 21，见 §3.1；jlink 运行时与其同源，AV_JDK 可覆写）
cd ../AnimeViewerService && mvn -DskipTests package
# 2) 打包（beforeBuildCommand 自动跑 scripts/build-service.mjs：
#    jdeps 算模块集 ∪ 反射型基线 → jlink 裁剪 JRE → 拼装 src-tauri/resources/service/
#    { runtime/ ~50MB , service.jar 34MB , bin/aria2c+ffmpeg+ffprobe（D3 随包，435MB）,
#      licenses/（GPLv2/GPLv3 许可文本随包）}
#    → 前端 vue-tsc + vite 构建）
npm run app:build                      # 完整版：NSIS 199MB + 绿色 exe
AV_SKIP_MEDIA_BIN=1 npm run app:build  # 精简版：NSIS 80MB（产物重命名 -lite 区分）
#    二进制路径可覆写：AV_ARIA2C / AV_FFMPEG / AV_FFPROBE
```

- **桌面版实测数据落位**：`%APPDATA%\AnimeViewer\data`（token/SQLite/downloads）+ `%APPDATA%\AnimeViewer\logs`（`shell.log` 壳侧拉起诊断——**排查「内置服务不可达」先看此文件**，记录 resource_dir 与完整命令行，拉起失败/资源缺失也落盘；`service.log` 服务端输出）；
- **桥接韧性**：就绪判定为壳内 TCP 端口探测（不经 WebView2 网络栈）；桥接等待 120s 后转 15s 低频后台重试——杀软首次扫描 35MB jar + 4000+ JRE 文件可达分钟级，就绪后自动填充，无需重启；
- **dev 模式**：`npm run app:dev` 无拼装产物时壳静默跳过拉起，窗口内为纯 Web 功能。

## 5. 数据初始化与升级

- **媒体库**：设置页「媒体服务」→ 媒体库页添加目录（`directories` 表登记）→ 扫描入库（`media_files`）；下载目录 `data/downloads` 完成后自动触发增量扫描；
- **升级**：替换 jar 重启即可——启动时 `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ... ADD COLUMN`（try-catch 幂等）自动迁移存量库，最终 schema 与附录 A 一致；前端替换 `dist/` 即可。

## 6. 备份与端口清单

- **备份**：整目录拷贝 `data/`（`media.db` + WAL/SHM + `token`；downloads 为下载产物可另行策略）；恢复 = 原位放回 + 重启；
- **端口**：8787（服务 HTTP）、16800（aria2 RPC，仅回环）；前端托管端口自定。

## 附录 A：SQLite 业务建表语句（v0.30.0，实测导出自运行库）

6 张业务表 + 7 个索引，应用启动时自动执行（无需手工建库）：

```sql
-- 媒体库目录（设置页登记的扫描根目录）
CREATE TABLE IF NOT EXISTS directories(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  path TEXT NOT NULL UNIQUE,
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL
);

-- 媒体文件索引（扫描 + ffprobe 探测 + 名称解析 + 绑定态）
CREATE TABLE IF NOT EXISTS media_files(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  dir_id INTEGER NOT NULL,
  path TEXT NOT NULL UNIQUE,
  name TEXT NOT NULL,
  ext TEXT NOT NULL,
  size INTEGER NOT NULL,
  mtime INTEGER NOT NULL,
  duration_sec REAL,
  container TEXT,
  vcodec TEXT,
  acodec TEXT,
  width INTEGER,
  height INTEGER,
  parsed_title TEXT,
  parsed_episode INTEGER,
  match_state TEXT NOT NULL DEFAULT 'unmatched',   -- unmatched/pending/bound
  subject_id INTEGER,
  subject_name TEXT,
  subject_name_cn TEXT,
  episode_sort INTEGER,
  auto_bound INTEGER NOT NULL DEFAULT 0,
  matched_at INTEGER,
  probed_at INTEGER,
  error TEXT,
  download_task_id INTEGER,     -- v0.16 迁移列：来源下载任务溯源
  ai_match_score INTEGER,       -- v0.30 迁移列：AI 匹配置信度 0~100
  ai_match_reason TEXT          -- v0.30 迁移列：AI 判定依据
);
CREATE INDEX IF NOT EXISTS idx_files_dir     ON media_files(dir_id);
CREATE INDEX IF NOT EXISTS idx_files_subject ON media_files(subject_id);
CREATE INDEX IF NOT EXISTS idx_files_state   ON media_files(match_state);

-- 下载任务台账（aria2 watcher 单向同步）
CREATE TABLE IF NOT EXISTS download_tasks(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  gid TEXT,
  infohash TEXT,
  name TEXT,
  uri TEXT NOT NULL,
  subject_id INTEGER,
  subject_name TEXT,
  subject_name_cn TEXT,
  episode_sort INTEGER,
  status TEXT NOT NULL DEFAULT 'queued',  -- queued/metadata/downloading/paused/completed/error
  total_len INTEGER NOT NULL DEFAULT 0,
  completed_len INTEGER NOT NULL DEFAULT 0,
  download_speed INTEGER NOT NULL DEFAULT 0,
  upload_speed INTEGER NOT NULL DEFAULT 0,
  connections INTEGER NOT NULL DEFAULT 0,
  seeds INTEGER NOT NULL DEFAULT 0,
  files_json TEXT,
  error TEXT,
  recover_count INTEGER NOT NULL DEFAULT 0,
  postprocessed INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  completed_at INTEGER
);
CREATE INDEX IF NOT EXISTS idx_tasks_status ON download_tasks(status);
CREATE UNIQUE INDEX IF NOT EXISTS idx_tasks_infohash ON download_tasks(infohash)
  WHERE infohash IS NOT NULL AND status IN ('queued','metadata','downloading','paused');

-- 运行期设置 KV（下载/订阅/AI/站点管理等前端可写配置，JSON 单行）
CREATE TABLE IF NOT EXISTS settings(
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

-- 条目级订阅（一 subject 一行）
CREATE TABLE IF NOT EXISTS subscriptions(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  subject_id INTEGER NOT NULL UNIQUE,
  subject_name TEXT,
  subject_name_cn TEXT,
  auto INTEGER NOT NULL DEFAULT 0,            -- v0.20 起弃用，列保留兼容
  min_episode INTEGER NOT NULL DEFAULT 0,     -- 观看进度基线
  ignored_fansubs TEXT NOT NULL DEFAULT '[]',
  last_checked_at INTEGER,
  last_hit_at INTEGER,
  created_at INTEGER NOT NULL,
  auto_score INTEGER,          -- v0.20 迁移列：匹配度阈值自动入队（0=全手动）
  last_check_error TEXT,       -- v0.20 迁移列
  ai_keywords TEXT,            -- v0.22 迁移列：AI 关键词扩展缓存
  rss_url TEXT                 -- v0.25 迁移列：RSS 固定直链
);

-- 订阅命中台账（待确认队列与历史共用；status=pending/enqueued/ignored/auto）
CREATE TABLE IF NOT EXISTS sub_hits(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  subject_id INTEGER NOT NULL,
  subject_name TEXT,
  subject_name_cn TEXT,
  episode_sort INTEGER,
  title TEXT NOT NULL,
  fansub TEXT,
  magnet TEXT NOT NULL,
  infohash TEXT,
  site TEXT,
  size TEXT,
  pub_date INTEGER,
  status TEXT NOT NULL DEFAULT 'pending',
  note TEXT,
  created_at INTEGER NOT NULL,
  decided_at INTEGER,
  score INTEGER,          -- v0.20 迁移列：命中匹配度
  score_detail TEXT,      -- v0.20 迁移列：评分依据
  ai_verdict TEXT         -- v0.22 迁移列：AI 命中语义判定 JSON
);
CREATE INDEX IF NOT EXISTS idx_sub_hits_status  ON sub_hits(status);
CREATE INDEX IF NOT EXISTS idx_sub_hits_subject ON sub_hits(subject_id, episode_sort);
```

> 说明：DDL 从运行库 `sqlite_master` 实测导出。存量老库的迁移列由启动时 `ALTER TABLE ... ADD COLUMN`（try-catch 幂等）追加，故其 `sqlite_master` 原文中迁移列显示在表尾，语义与上面整理后的形态完全一致。
