1. v0 搜索接口的 `images` 字段语义与 legacy 接口不同（搜索的 common=400px、large=原图、medium=800px）——图片清晰度已改为「URL 路径规范化」方案，不依赖字段名

**v0.5 实测中的重要发现（已记录）**：
1. **`filter.air_date` 的 `<=` 表达式服务端恒匹配 0 条**（官方示例仅用 `>=` 与 `<`；数字字段的 `<=` 如 `rating_count`/`rank` 则正常）——年份上限已改为 `<（次年）-01-01` 表达
2. **官方 v0 无目录列表端点**：`GET /v0/indices` 返回 404（仅 `POST` 创建目录需 `write:indices` 授权），只能按 ID 查看——D5 据此调整方案
3. **搜索后端（meilisearch 相关路径）当天出现过间歇性退化**：`filter.tag`/`filter.meta_tags`/角色/人物搜索一度恒返回 0 条（v0.4 实测时 tag 过滤为 20 条），数小时后角色/人物搜索恢复，**但 tag 过滤复测仍为 0**——v0.4 的标签搜索功能（A1/A2）受服务端行为影响存在回归风险，客户端代码正确，恢复后即自动生效
4. 演示模式全量兜底：年代浏览/关联条目/目录/角色人物搜索/高级筛选均有演示数据实现；并修复「切数据源后年代浏览不重载」「小众佳作预设无其他条件时不触发搜索」两个交互缺陷

### A.3 硬约束与风险

1. **v0 无「删除收藏」端点**：`/v0/users/-/collections/{subject_id}` 仅支持 POST（upsert）与 PATCH（进度），规范中全部 4 个 DELETE 方法均在目录（indices）相关路径上。因此本地取消收藏/抛弃状态**无法推送云端**，与 v0.3「4=搁置 5=抛弃 不同步」的处理一致。
2. **搜索接口仍为实验性 API**：D3/D4 依赖的 filter 字段 Schema 可能变动——延续「API 层单文件收口」对策。**v0.5 实测结论**：`meta_tags` 服务端过滤不可用（与 tag 一同恒 0），D4 按预案保留客户端排除；另发现 `air_date` 不支持 `<=`（已绕开）。
3. **单集 PUT 与批量 PATCH 并存**：E1 上线后两条写路径并存，需在同步队列中统一（单集标记同样入 dirty 队列重放）。
